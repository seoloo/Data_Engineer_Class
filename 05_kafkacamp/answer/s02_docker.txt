--------------------------------------------------------------------------------
[02-1] Kafka 를 띄우십시오. C:\kafkacamp 에서 kafka1.yml 로 컨테이너를 켭니다. (-d 는 "뒤에서 돌려라")
[어디서] PowerShell (VS Code 아래 터미널, C:\kafkacamp)
--------------------------------------------------------------------------------
docker compose -f kafka1.yml up -d

── 결과 (학생 PC 화면 — 아이디·시각·버전 숫자는 PC 마다 다름) ──
[+] Running 3/3
 ✔ kafka Pulled                      38.2s
 ✔ Network kafka1_default  Created   0.1s
 ✔ Container kafka         Started   0.8s

→ 처음 한 번은 이미지를 받는(Pulling) 줄이 먼저 나옵니다(1~3분). 그 다음 네트워크 하나와 컨테이너 kafka 가 생깁니다. no
configuration file provided 오류가 나면 터미널이 C:\kafkacamp 가 아닌 곳에 있는 것입니다(cd C:\kafkacamp). -d
를 빼면 Kafka 의 로그가 터미널을 가득 채우고 터미널을 돌려주지 않습니다.

--------------------------------------------------------------------------------
[02-2] 켜진 컨테이너 목록을 보십시오.
[어디서] PowerShell (VS Code 아래 터미널, C:\kafkacamp)
--------------------------------------------------------------------------------
docker ps

── 결과 (학생 PC 화면 — 아이디·시각·버전 숫자는 PC 마다 다름) ──
CONTAINER ID   IMAGE                COMMAND                  CREATED          STATUS          PORTS                    NAMES
3f2a9c1d7b44   apache/kafka:4.3.1   "/__cacert_entrypoin…"   25 seconds ago   Up 24 seconds   0.0.0.0:9092->9092/tcp   kafka

→ NAMES 가 kafka, IMAGE 가 apache/kafka:4.3.1, STATUS 가 Up, PORTS 에 9092->9092. 이 네 가지만 보면
됩니다. 컨테이너 아이디는 PC 마다 다릅니다.

[02-2 바꿔 보기 ①] 컨테이너를 멈추면? — stop 하고 docker ps, 다시 start
docker compose -f kafka1.yml stop
docker ps
docker compose -f kafka1.yml start
docker ps

── 결과 ──
[+] Stopping 1/1
 ✔ Container kafka  Stopped        1.2s
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES
[+] Running 1/1
 ✔ Container kafka  Started        0.5s
CONTAINER ID   IMAGE                COMMAND                  CREATED         STATUS         PORTS                    NAMES
3f2a9c1d7b44   apache/kafka:4.3.1   "/__cacert_entrypoin…"   3 minutes ago   Up 2 seconds   0.0.0.0:9092->9092/tcp   kafka

→ 이래서 — stop 하면 docker ps 목록에서 사라지고, start 하면 다시 Up. stop/start 는 전원 끄고 켜기라 만든 토픽과 메시지가 남아
있습니다. 반대로 docker compose -f kafka1.yml down 은 컨테이너를 지워 버리므로 토픽과 메시지도 같이 사라집니다. 수업 중간에는
down 을 쓰지 않습니다 — 정말 처음부터 다시 할 때만.

--------------------------------------------------------------------------------
[02-3] Kafka 가 다 켜졌는지 로그에서 확인하십시오. (로그 중 started 가 들어간 줄만)
[어디서] PowerShell (VS Code 아래 터미널, C:\kafkacamp)
--------------------------------------------------------------------------------
docker logs kafka | Select-String "Kafka Server started"

── 결과 (학생 PC 화면 — 아이디·시각·버전 숫자는 PC 마다 다름) ──
[2026-10-16 09:02:11,482] INFO [KafkaRaftServer nodeId=1] Kafka Server started (kafka.server.KafkaRaftServer)

→ 이 줄이 보이면 손님(프로듀서 · 컨슈머)을 받을 준비가 끝난 것입니다. 안 보이면 10초 뒤 다시 칩니다. nodeId=1 이 kafka1.yml 의
KAFKA_NODE_ID 입니다.

--------------------------------------------------------------------------------
[02-4] 컨테이너 안으로 들어가서 Kafka 버전을 확인하고, 다시 나오십시오. (세 줄을 한 줄씩)
[어디서] PowerShell (VS Code 아래 터미널, C:\kafkacamp)
--------------------------------------------------------------------------------
docker exec -it kafka bash
./kafka-topics.sh --version
exit

── 결과 (학생 PC 화면 — 아이디·시각·버전 숫자는 PC 마다 다름) ──
kafka:/opt/kafka/bin$ ./kafka-topics.sh --version
4.3.1
kafka:/opt/kafka/bin$ exit
exit
PS C:\kafkacamp>

→ docker exec -it kafka bash = "kafka 컨테이너 안에서 bash(리눅스 터미널)를 열어 달라". 프롬프트가 PS
C:\kafkacamp> 에서 kafka:/opt/kafka/bin$ 같은 리눅스 모양으로 바뀝니다(모양은 조금 다를 수 있음). 지금 서 있는 곳이 Kafka
명령들이 있는 폴더라 ./kafka-topics.sh 처럼 앞에 ./ 를 붙여 실행합니다. exit 로 다시 PowerShell 로 나옵니다. STEP 03 부터
이 "들어가기" 를 매번 합니다.

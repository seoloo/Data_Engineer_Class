[04-3] 키를 붙여서 세 줄을 보내십시오. 줄마다 키:값 모양입니다.

[04-4] 처음부터 읽되 파티션 · 오프셋 · 키를 같이 찍으십시오.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
./kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic tags3 --from-beginning --formatter-property print.partition=true --formatter-property print.offset=true --formatter-property print.key=true

── 결과 (Kafka 4.3.1 화면 형식 — 작성 환경에서 같은 동작을 재현) ──
The consumer rebalance protocol (KIP-848) is production-ready! Set group.protocol=consumer to try it out. See https://kafka.apache.org/documentation/#consumer_rebalance_protocol
Partition:2	Offset:0	C001	IN S01
Partition:2	Offset:1	C001	OUT S03
Partition:0	Offset:0	C002	IN S06
Processed a total of 3 messages

→ C001 두 줄이 같은 Partition:2, C002 는 Partition:0. 그리고 오프셋이 장부마다 0부터 — 2번 장부에 0 · 1, 0번 장부에
0. 보낸 순서는 C001 · C002 · C001 이었는데, 화면 순서는 장부별로 묶여 나올 수 있습니다. Kafka 가 지키는 순서는 "한 파티션 안"
뿐입니다.

org.apache.kafka.common.KafkaException: No key separator found on line number 1: 'C004 IN S01'

[04-10 바꿔 보기 ①] 파티션을 2개로 줄이면?
./kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic tags3 --partitions 2

── 결과 ──
Error while executing topic command : Topic currently has 4 partitions, which is higher than the requested 2.
[ERROR] org.apache.kafka.common.errors.InvalidPartitionsException: Topic currently has 4 partitions, which is higher than the requested 2.

→ 이래서 — 줄이기는 안 됩니다. 줄이려면 장부를 합쳐야 하는데, 그러면 각 장부의 오프셋과 순서가 깨지기 때문입니다. 정말 줄여야 하면 새 토픽을 만들어
옮깁니다. 파티션 수는 "늘릴 수는 있지만 줄일 수는 없다" — 프로젝트 1단계 설계표에 꼭 적는 한 줄입니다.

[04-11] C001 로 한 줄 더 보내고, 그 줄이 몇 번 파티션에 갔는지 보십시오.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
./kafka-console-producer.sh --bootstrap-server localhost:9092 --topic tags3 --reader-property parse.key=true --reader-property key.separator=:
>C001:IN S02
>(Ctrl+C)
./kafka-get-offsets.sh --bootstrap-server localhost:9092 --topic tags3

── 결과 (Kafka 4.3.1 화면 형식 — 작성 환경에서 같은 동작을 재현) ──
tags3:0:3
tags3:1:2
tags3:2:11
tags3:3:0

→ 이번에는 1번 파티션이 하나 늘었습니다(2 → 3). 예전 C001 은 2번 장부에 있는데 새 C001 은 1번 장부로 — 파티션 수가 바뀌면 같은 키의
자리가 바뀝니다(해시값 % 4 ≠ 해시값 % 3). C001 의 "승차 → 하차" 순서가 두 장부에 쪼개질 수 있습니다. 그래서 파티션 수는 처음에 넉넉히
정합니다.

[03-0] VS Code 터미널(PowerShell)에서 kafka 컨테이너 안으로 들어가십시오. 이 STEP 의 나머지는 모두 이 안에서 칩니다.
[어디서] PowerShell (VS Code 아래 터미널, C:\kafkacamp)
--------------------------------------------------------------------------------
docker exec -it kafka bash

── 결과 (학생 PC 화면) ──
kafka:/opt/kafka/bin$

→ 프롬프트가 리눅스 모양으로 바뀌면 들어간 것입니다. Error response from daemon: No such container: kafka 면
Kafka 가 안 켜져 있는 것 — exit 할 필요 없이 docker compose -f kafka1.yml up -d 부터.

[03-1] hello 라는 토픽을 만드십시오.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
./kafka-topics.sh --bootstrap-server localhost:9092 --create --topic hello

── 결과 (Kafka 4.3.1 화면 형식 — 작성 환경에서 같은 동작을 재현) ──
Created topic hello.

→ 파티션 수 · 복제 수를 주지 않았으니 기본값(1개 · 1개) 으로 만들어집니다(03-3 에서 확인).

--------------------------------------------------------------------------------
[03-2] 토픽 목록을 보십시오.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
./kafka-topics.sh --bootstrap-server localhost:9092 --list

── 결과 (Kafka 4.3.1 화면 형식 — 작성 환경에서 같은 동작을 재현) ──
hello

→ hello 하나. (Kafka 가 내부에서 쓰는 __consumer_offsets 같은 이름은 컨슈머 그룹을 쓰기 시작하면 생깁니다)

--------------------------------------------------------------------------------
[03-3] hello 토픽을 자세히 보십시오.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
./kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic hello

── 결과 (Kafka 4.3.1 화면 형식 — 작성 환경에서 같은 동작을 재현) ──
Topic: hello	TopicId: X3XkycXULMAn7EZMGnFR6Q	PartitionCount: 1	ReplicationFactor: 1	Configs: 
	Topic: hello	Partition: 0	Leader: 1	Replicas: 1	Isr: 1	Elr: 	LastKnownElr: 

→ 첫 줄: PartitionCount: 1 · ReplicationFactor: 1. 둘째 줄부터 파티션마다 한 줄 — Partition: 0 · Leader:
1 · Replicas: 1 · Isr: 1. "0번 파티션은 1번 브로커가 맡고, 복사본은 1번에만 있다". 파티션과 복제는 STEP 04 · 10 에서
다룹니다. 지금은 TopicId 는 PC 마다 다르다 만.

--------------------------------------------------------------------------------
[03-4] 콘솔 프로듀서를 켜고 메시지 세 줄을 보내십시오. 줄마다 Enter, 다 치면 Ctrl+C.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
./kafka-console-producer.sh --bootstrap-server localhost:9092 --topic hello
>hello kafka
>second message
>third message
>(Ctrl+C)

── 결과 (Kafka 4.3.1 화면 — 프롬프트 > 뒤에 친 글자만 보인다) ──
(출력 없음)

→ > 는 "한 줄 치세요" 라는 프롬프트입니다. Enter 를 칠 때마다 메시지 하나가 보내집니다. 아무 대답이 없는 것이 정상입니다.

--------------------------------------------------------------------------------
[03-5] 처음부터 읽어 보십시오. 세 줄이 보이면 Ctrl+C.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
./kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic hello --from-beginning

── 결과 (Kafka 4.3.1 화면 형식 — 작성 환경에서 같은 동작을 재현) ──
The consumer rebalance protocol (KIP-848) is production-ready! Set group.protocol=consumer to try it out. See https://kafka.apache.org/documentation/#consumer_rebalance_protocol
hello kafka
second message
third message
Processed a total of 3 messages

→ 보낸 순서 그대로 세 줄. 그리고 Ctrl+C 를 누를 때까지 끝나지 않습니다 — 새 메시지를 기다리고 있기 때문입니다. 이것이 "끝나지 않는 표"(1과목
STEP 18)의 진짜 모습입니다.

[03-6] 창 두 개로 합니다. 창 ① 에서 --from-beginning 을 빼고 컨슈머를 켜 두고, VS Code 터미널 오른쪽 위 + 로 창 ② 를 새로 열어 컨테이너에 들어간 뒤 프로듀서로 fourth message 를 보내십시오.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
# [창 ① — 지금 창] 컨슈머를 켜 두기만 합니다 (여기에는 아무것도 치지 않습니다)
./kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic hello

# [창 ② — + 로 새로 연 터미널] PS C:\kafkacamp> 에서 시작
docker exec -it kafka bash
./kafka-console-producer.sh --bootstrap-server localhost:9092 --topic hello
>fourth message
>(Ctrl+C)

# [창 ①] fourth message 가 뜬 것을 보고 Ctrl+C

── 결과 (창 ① 의 화면 — Kafka 4.3.1) ──
The consumer rebalance protocol (KIP-848) is production-ready! Set group.protocol=consumer to try it out. See https://kafka.apache.org/documentation/#consumer_rebalance_protocol
fourth message
Processed a total of 1 messages

→ 켜자마자는 안내문 한 줄 말고 아무것도 안 나옵니다 — 기본은 "지금부터 오는 것만". 창 ② 에서 fourth message 를 치는 순간 창 ① 에 바로
뜹니다. 예전 세 줄은 안 보입니다. 메시지는 그대로 있고, 어디서부터 읽느냐만 다릅니다. Ctrl+C 를 누르면 Processed a total of 1
messages — 받은 개수가 1 이어야 제대로 한 것입니다.

[03-6 바꿔 보기 ①] 창 ② 를 열지 않고 창 ① (컨슈머가 도는 창)에 직접 fourth message 를 치면?
./kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic hello
fourth message          ← 컨슈머 창에 그대로 친 것
(Ctrl+C)

── 결과 ──
The consumer rebalance protocol (KIP-848) is production-ready! Set group.protocol=consumer to try it out. See https://kafka.apache.org/documentation/#consumer_rebalance_protocol
fourth message
^CProcessed a total of 0 messages

→ 이래서 — 글자는 화면에 보이지만 Kafka 로 간 것이 아닙니다. 터미널은 키보드로 친 글자를 그대로 화면에 보여 줄 뿐이고, 컨슈머는 읽기만 하는
프로그램이라 입력을 받지 않습니다. 그래서 Ctrl+C 를 누르면 Processed a total of 0 messages — 받은 것이 0개입니다. 0 이
나오면 창 ② 를 열어 프로듀서로 다시 보냅니다. 이대로 넘어가면 03-9 가 hello:0:16 이 아니라 15 가 됩니다. 교육장에서 가장 많이 나오는
실수입니다.

[03-7] 파일을 통째로 보내십시오. 컨테이너 안 /data 는 내 PC 의 C:\kafkacamp\data 입니다.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)

── 결과 (Kafka 4.3.1 화면 형식 — 작성 환경에서 같은 동작을 재현) ──
>>>>>>>>>>>>>

→ > 가 13개 줄줄이 찍히고 끝납니다. 파일 한 줄(12줄) = 메시지 하나씩, 마지막 하나는 "더 없음" 을 확인한 프롬프트입니다. < 는 "키보드 대신 이
파일을 입력으로" 라는 리눅스 기호입니다.

[03-9] hello 토픽에 메시지가 몇 개 쌓였는지 보십시오.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
./kafka-get-offsets.sh --bootstrap-server localhost:9092 --topic hello

── 결과 (Kafka 4.3.1 화면 형식 — 작성 환경에서 같은 동작을 재현) ──
hello:0:16

→ hello:0:16 = "토픽 hello 의 0번 파티션, 다음에 적힐 번호는 16". 0번부터 15번까지 16개(손으로 4 + 파일 12). 오프셋은 0부터
세기 때문에 마지막 메시지의 번호는 15 입니다.

[03-10] 일부러 틀려 보십시오. 프로듀서의 토픽 이름을 helo 로 잘못 쳐서 한 줄 보내고, 목록을 보십시오.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
./kafka-console-producer.sh --bootstrap-server localhost:9092 --topic helo
>oops
>(Ctrl+C)
./kafka-topics.sh --bootstrap-server localhost:9092 --list

── 결과 (Kafka 4.3.1 화면 형식 — 작성 환경에서 같은 동작을 재현) ──
hello
helo

→ 오류가 아니라 helo 라는 토픽이 새로 생겼습니다. Kafka 는 기본 설정에서 없는 토픽에 보내면 알아서 만들어
줍니다(auto.create.topics.enable). 화면에 WARN ... UNKNOWN_TOPIC_OR_PARTITION 줄이 한 번 지나갈 수 있습니다.
1과목의 "조용한 실수" 와 같은 종류입니다 — 실무에서는 이 기능을 끄고, 토픽은 미리 설계해서 만듭니다(프로젝트 1단계).

[03-11] 잘못 생긴 helo 토픽을 지우고 목록을 다시 보십시오.
[어디서] kafka 컨테이너 안 (docker exec -it kafka bash 로 들어간 터미널)
--------------------------------------------------------------------------------
./kafka-topics.sh --bootstrap-server localhost:9092 --delete --topic helo
./kafka-topics.sh --bootstrap-server localhost:9092 --list

── 결과 (Kafka 4.3.1 화면 형식 — 작성 환경에서 같은 동작을 재현) ──
hello

→ 지우기는 아무 말 없이 끝나고, 목록에서 helo 가 사라집니다. 토픽을 지우면 안의 메시지도 전부 사라집니다 — 되돌릴 수 없습니다. 윈도에 Kafka 를
직접 깔았다면 이 명령에서 브로커가 죽는 일이 있어서 Docker 를 씁니다.

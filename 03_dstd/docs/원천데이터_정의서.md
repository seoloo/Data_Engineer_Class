## 1. `cust_master.csv` — 회원관리 시스템

| 항목 | 값 |
|---|---|
| 인코딩 | **EUC-KR** |
| 줄바꿈 | CRLF |
| 구분자 | 쉼표 |
| 헤더 | 있음 |
| 행 수 | 300 (수업용 소형본 8) |

| 컬럼 | 원천 의미 | 형 | 비고 |
|---|---|---|---|
| `CUST_NO` | 회원번호 | 문자 7 | **선행 0 있음.** 정수로 변환하면 손실 |
| `CUST_NM` | 회원명 | 문자 | 합성 데이터 |
| `HP` | 휴대폰 | 문자 | `010-0000-XXXX` 대역 (합성) |
| `EMAIL` | 이메일 | 문자 | **결측 있음.** 필수 항목 아님 |
| `JOIN_DT` | 가입일 | 문자 | 날짜 형식 4종 혼재 |
| `GRD_CD` | 회원등급 | 문자 3 | `G01`~`G04` |
| `ADDR_SIDO` | 주소 시도 | 문자 | 17개 시도명 |
| `DEL_YN` | 탈퇴 여부 | 문자 1 | `Y`/`N`. `Y`는 오류가 아님 |

**읽는 법**

```python
import pandas as pd
cust = pd.read_csv("data/raw/common/cust_master.csv",
                   encoding="euc-kr",   # UTF-8로 읽으면 UnicodeDecodeError
                   dtype=str)           # 선행 0 보존
```

## 2. `order_2026.csv` — 구 주문관리 시스템

| 항목 | 값 |
|---|---|
| 인코딩 | **UTF-8 (BOM 포함)** |
| 줄바꿈 | CRLF |
| 구분자 | 쉼표 |
| 헤더 | 있음 |
| 행 수 | 3,952 (수업용 소형본 41) |
| 기간 | 2026-01-01 ~ 2026-07-31 |
| 한 행의 의미 | **주문 항목.** 복합키 `ORD_NO` + `ORD_SEQ` |

| 컬럼 | 원천 의미 | 형 | 비고 |
|---|---|---|---|
| `ORD_NO` | 주문번호 | 문자 | `ORD26######` |
| `ORD_SEQ` | 주문 항목 순번 | 문자 | 1부터 |
| `CUSTNO`\* | 회원번호 | 문자 7 | 회원 파일의 `CUST_NO`와 **이름이 다름.** 공란·`GUEST` 있음 |
| `GOODS_CD`\* | 상품코드 | 문자 4 | 상품 API의 `goodsCode`와 **이름이 다름.** 선행 0 있음 |
| `ORD_DT` | 주문일 | 문자 | 형식 4종 혼재 + **존재하지 않는 날짜 6주문 13행** |
| `QTY` | 수량 | 문자 | 정수 |
| `AMT` | 항목 실판매금액 | 문자 | `12000` / `12,000` / `" 12000 "` / `12000.0` 혼재 |
| `ORD_ST` | 주문상태 | 문자 | 표기 혼재 + 정의 없는 값 7주문 20행 |
| `PAY_MTHD` | 결제수단 | 문자 | `CARD`/`BANK`/`VBANK`/`MOBILE` + `ETC` 9주문 30행 |
| `DLV_FEE` | 배송비 | 문자 | **주문 단위 값이 모든 항목 행에 반복 기재됨.** 드물게 항목마다 다른 주문 있음 |
| `CANCEL_DT` | 취소일 | 문자 | 비어 있으면 취소 아님. ISO 형식 |

\* 팀별로 컬럼명이 다릅니다. 업무설명서 6절 참조.

**읽는 법**

```python
order = pd.read_csv("data/raw/common/order_2026.csv",
                    encoding="utf-8-sig",  # BOM 제거
                    dtype=str)             # 선행 0·금액 표기 보존
```

> **도구에 따라 결과가 다릅니다.** pandas의 `read_csv`는 UTF-8 BOM을 자동으로 걷어냅니다.
> 그러나 Python 내장 `open()` + `csv` 모듈은 걷어내지 않아 첫 컬럼명이 `'﻿ORD_NO'`가
> 됩니다. MySQL `LOAD DATA INFILE`도 마찬가지입니다.
> 그래서 `encoding="utf-8-sig"`를 **습관으로 붙이는 것**이 안전합니다.

## 3. `product_api_response.json` — 신 상품 시스템 API 응답

| 항목 | 값 |
|---|---|
| 인코딩 | UTF-8 |
| 구조 | 최상위 객체 → `items` 배열 |
| 건수 | 80 (수업용 소형본 6) |
| 명명 규칙 | **camelCase** — 앞의 두 CSV와 충돌 |

```json
{
  "resultCode": "00",
  "resultMsg": "정상",
  "totalCount": 80,
  "items": [
    {
      "goodsCode": "0001",
      "goodsName": "극세사 걸레 4입",
      "categoryName": "청소",
      "unitPrice": 12900,
      "currency": "KRW",
      "taxType": "TAX",
      "useYn": "Y",
      "regDate": "2023-08-11"
    }
  ]
}
```

| 필드 | 원천 의미 | 비고 |
|---|---|---|
| `goodsCode` | 상품코드 | 문자 4. **선행 0 있음** |
| `goodsName` | 상품명 | |
| `categoryName` | 카테고리명 | 주방/욕실/청소/수납/침구/생활잡화 |
| `unitPrice` | 정가 | **통화에 따라 단위가 다름.** 실판매가 아님 |
| `currency` | 통화 | `KRW` 기본, 일부 `USD`·`JPY` |
| `taxType` | 과세구분 | `TAX`/`FREE` + 정의 없는 `Z` 2건 |
| `useYn` | 판매 여부 | `N`은 판매 중지. 오류 아님 |
| `regDate` | 등록일 | 날짜 형식 혼재 |

**읽는 법**

```python
import json
with open("data/raw/common/product_api_response.json", encoding="utf-8") as f:
    payload = json.load(f)
prod = pd.DataFrame(payload["items"])   # items 아래로 한 단계 들어가야 표가 나온다
```

## 4. 세 원천의 식별자 대응

| 표준 논리명 | 회원 파일 | 주문 파일(공통) | 상품 API |
|---|---|---|---|
| 고객번호 | `CUST_NO` | `CUSTNO` | — |
| 상품코드 | — | `GOODS_CD` | `goodsCode` |

같은 대상을 가리키는데 이름이 셋입니다.
이 표가 **원천 → 표준 매핑표의 출발점**이며, 컬럼명을 바꾸는 것만으로는
표준화가 끝나지 않습니다. 값의 형(type), 자릿수, 허용값, 코드 체계까지 맞춰야 합니다.

## 5. 파일 다루기 원칙

- `data/raw/`는 **읽기 전용**입니다. 절대 덮어쓰지 마십시오.
- 중간 산출물은 `data/work/`, 최종 결과는 `data/out/`에 씁니다.
- 격리한 행은 `logs/`에 원인과 함께 남깁니다.
- 데이터를 다시 만들어야 하면 `src/make_dataset.py`를 같은 인자로 재실행하십시오.
  같은 파일이 그대로 나옵니다.
